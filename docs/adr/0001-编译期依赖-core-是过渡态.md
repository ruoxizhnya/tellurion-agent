# 0001 · 编译期依赖 core 是过渡态

- **状态**：已裁决（来源：ADR-D29 §7-S3 / ADR-D10 / QT-07、QT-17、QT-50）
- **场景**：拆仓时 agent 直接 import core 的 20 个包（domain 48 处、storage 14、strategy 11…）。要让"单仓可构建"成立，必须把这些依赖降级为 HTTP + 契约；但一次性做完会让 W0/W1 的 breaking 改动无处落地。
- **决策**：① 承认 `replace tellurion => ../tellurion` 是**过渡态**，写进 AGENTS.md，且是唯一允许的仓外 replace；② 删它的时点定在 S3，前置是 QT-50（HTTP 粗粒度）+ QT-17（数据自持）；③ 在此之前，任何新增的 core 依赖都要单独评审（不许"顺手 import 一下"）。
- **理由**："能编译"和"能独立"是两件事。先用 replace 保住编译，才能让 W0 的契约冻结（abi v2）先落地；否则拆仓和契约改造互相阻塞，两边都做不完。
- **代价 / 后果**：① agent 的 R1（单仓可构建）长期是 known-gap，必须显式登记而不是假装绿；② core 的 breaking 会在 agent 侧静默烂掉 → 用 QT-18 的 `agent-compat` job 兜住；③ `replace` 让"本地改了 core 就能用"成为习惯，会推迟真正解耦。
- **替代关系**：无（本仓首条）
